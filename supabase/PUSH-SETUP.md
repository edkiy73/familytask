# Web Push: пуши даже в закрытое приложение

После этой настройки уведомления о дедлайнах и событиях семьи будут приходить
на устройства, даже когда приложение закрыто. Клиентская часть уже встроена в
`index.html`, ключи уже вписаны. Осталось поднять серверную часть — 4 шага,
~10 минут, всё в пределах бесплатного тарифа Supabase
(Edge Functions: 500K вызовов/мес, крон тратит ~44K).

## 1. Supabase CLI и деплой функций
```bash
npm i -g supabase          # если ещё нет
cd <эта папка supabase/>
supabase login
supabase link --project-ref qviioxefqtnhashdbtls
supabase functions deploy push-send --no-verify-jwt
supabase functions deploy push-cron --no-verify-jwt
```

## 3. SQL
Выполните `supabase-push.sql` в SQL Editor (таблицы подписок, RPC, расписание
pg_cron). URL проекта и cron-секрет в него уже вписаны.

## 4. Проверка
1. Задеплойте свежий `index.html` (в нём VAPID-ключ и отправка событий).
2. На устройстве: Семья → «Уведомления» → включить. Подписка уйдёт в облако
   автоматически (в карточке появится строка «Пуши в закрытое приложение: да»).
3. Поставьте дело с дедлайном через 2–3 минуты, закройте приложение полностью —
   пуш должен прийти.
4. Создайте дело со второго устройства — на первое прилетит «🆕 Новое дело»,
   даже если приложение закрыто.

## Как это устроено
- **События** (новое дело, назначение, выполнение): устройство-автор после
  синка вызывает `push-send`, та рассылает Web Push всем подпискам семьи,
  кроме отправителя. Мёртвые подписки чистятся автоматически.
- **Дедлайны**: pg_cron раз в минуту дёргает `push-cron` (с секретом), функция
  сканирует состояния семей, находит «скоро» (за 30 мин) и «наступил»,
  анти-дубль — атомарной вставкой в `hub_push_log`.
- Локальные уведомления в открытом приложении используют те же `tag`,
  поэтому серверный и локальный пуш не дублируются, а заменяют друг друга.
- iPhone: пуши работают только у PWA, добавленной на экран «Домой» (iOS 16.4+).
