# Уведомления · как всё работает и как проверить

## Что было не так и что исправлено

1. **Дедлайны дублировались** — их слал и телефон локально, и сервер (крон).
   Теперь: если серверный Web Push активен, телефон **не** показывает дедлайны
   локально — их шлёт только крон. Локальный показ остаётся лишь как запасной
   вариант (когда пуши не настроены).

2. **Приходило всем, а не исполнителю** — подписки устройств не хранили, за каким
   профилем они закреплены (`member`). Теперь при входе в профиль устройство
   переподписывается с актуальным `member`, а сервер шлёт адресно.

3. **Смена исполнителя не слала уведомление** — та же причина (пустой `member` в
   подписке). После переустановки SQL и переподписки — работает.

4. **«Новое дело» уходило всем даже для личных заметок** — теперь заметка
   отправляется только тем, кому она видна; дело — всем, а исполнителю
   дополнительно «Вам назначено».

## Кто какое уведомление получает

| Событие | Кому приходит |
|---|---|
| Новое **дело** | Всем в семье (кроме автора) |
| Новое дело **с исполнителем** | Всем «Новое дело» + исполнителю «Вам назначено» |
| Новая **заметка** | Только тем, кому она видна (по «Кто видит») |
| Смена исполнителя | Новому исполнителю |
| Напоминание («Напомнить») | Исполнителю; если дело «Общее» — всем |
| Дело выполнено | Всем в семье |
| Дедлайн (скоро / наступил) | Исполнителю; если «Общее» — всем |

## Что нужно сделать (по порядку)

Функции и секреты у тебя уже загружены. Осталось:

### 1. Обновить SQL
Выполни `supabase-full.sql` целиком в Supabase → SQL Editor → **Run**.
Он пересоздаёт таблицы и функции, в т.ч. `hub_subs.member` и `hub_sub_put`
с параметром участника.

### 2. Передеплоить обе edge-функции (код изменился в обеих)
```
supabase functions deploy push-send --no-verify-jwt
supabase functions deploy push-cron --no-verify-jwt
```
> Файлы — в папке `supabase/functions/push-send/` и `supabase/functions/push-cron/`.

### 3. Переустановить приложение (важно!)
На **каждом устройстве**: открой приложение, обнови страницу (или переустанови
PWA), затем зайди в свой профиль. При входе устройство заново подпишется на push
с правильным `member`. Убедись, что уведомления **разрешены** (Профиль →
«Включить на этом устройстве»).

## Как проверить

1. На каждом устройстве: Профиль → **«Проверить все уведомления»**.
   - Покажет все виды локально.
   - Отправит **адресный** серверный тест (должен прийти только этому профилю).
   - Отправит тест **для всех** (придёт на все устройства семьи).
2. Проверка адресации между устройствами:
   - На устройстве А (профиль «Сергей») назначь дело на «Светлану».
   - Уведомление «Вам назначено» должно прийти **только** на устройство, где
     открыт профиль «Светлана» — и **не** прийти Сергею.
3. Проверка дедлайна без дублей:
   - Поставь дело с дедлайном через ~2 минуты, исполнитель — конкретный человек.
   - Уведомление придёт **один раз** и **только** исполнителю.

## Если что-то не приходит

- Убедись, что все устройства прошли шаг 3 (перезаход в профиль) — иначе их
  подписка старая, без `member`.
- Проверь в Supabase → Table editor → `hub_subs`, что у строк заполнена
  колонка `member` (id участника), а не пустая.
- iOS: пуши в закрытое приложение работают только для PWA, установленного на
  экран «Домой» (Safari → «Поделиться» → «На экран Домой»).
